two different sentences. they are not the same sentence.
addEventListener 

el.addEventListener('click', handler);
el.addEventListener('click', handler, { capture: true, once: true, passive: true });

many listeners live side by side
b.addEventListener('click', a);   a
b.addEventListener('click', b);   a, b   — both run

the old property has room for one
b.onclick = en;
b.onclick = to;                only 'to' survives

the exact same function, added three times
b.addEventListener('click', f); x3   → fires once. duplicates are ignored
removeEventListener 

this does nothing at all — a new function every time
el.addEventListener('click', () => lukk());
el.removeEventListener('click', () => lukk());   still fires
el.removeEventListener('click', obj.h.bind(obj)); still fires

keep the reference, and match the capture flag too
const h = () => lukk();
el.addEventListener('click', h, true);
el.removeEventListener('click', h);          no — flags differ
el.removeEventListener('click', h, true);    yes

two ways to never write it
el.addEventListener('click', h, { once: true });   3 clicks, 1 run

const ac = new AbortController();
el.addEventListener('click', h, { signal: ac.signal });
ac.abort();                                   removes all of them at once
propagation 

<div id="ytre"><div id="midt"><button id="indre">
one click on the button, six handlers, this order:

ytre    capture   eventPhase 1   down
midt    capture   eventPhase 1
indre   capture   eventPhase 2   at the target
indre   bubble    eventPhase 2
midt    bubble    eventPhase 3   up
ytre    bubble    eventPhase 3

without { capture: true } you only ever see the way up

focus does not bubble; focusin does the same job and bubbles
currentTarget 

listener on #ytre, the user clicks a <span> deep inside

e.target          → the span      what was clicked
e.currentTarget   → #ytre         who is listening
this              → #ytre         in a function(), same as currentTarget

but not in an arrow — it keeps the this from where it was written
el.addEventListener('click', () => this);   window, or undefined in a module

so: e.currentTarget always works. this only sometimes.
delegation 

one listener for a list that keeps changing
liste.addEventListener('click', (e) => {
  const knapp = e.target.closest('button');
  if (!knapp) return;               the click missed
  slett(knapp.dataset.id);
});

liste.innerHTML = '<li><button data-id="99">...';  all new buttons
→ still works. the listener was never on them.

closest is not optional: click a span inside the button
e.target                → SPAN
e.target.closest('button') → the button
preventDefault 

skjema.addEventListener('submit', (e) => {
  e.preventDefault();      the page does not reload
  send(new FormData(skjema));
});

measured, on a link with preventDefault:
  the address did not change          the default was cancelled
  the parent's handler still ran      the journey was not

e.defaultPrevented       → true   later handlers can see it

return false;                does nothing here. the link followed.
                         (it only means something in onclick="...")

and inside { passive: true } it is ignored, with a console error
stopPropagation 

two handlers on the button, one on the parent

e.stopPropagation()           → first, second        parent: no
e.stopImmediatePropagation()  → first               parent: no

and neither of them cancels anything:
lenke.addEventListener('click', (e) => e.stopPropagation());
→ the browser followed the link anyway

the other direction, from above:
ytre.addEventListener('click', (e) => e.stopPropagation(), true);
→ the button's own handler never ran. it was stopped on the way down.
