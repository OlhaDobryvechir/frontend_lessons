the await from lesson 6, explained

const res = await fetch(url);

fetch hands back a promise immediately — a receipt, not an answer.
await pauses this function, lets the page keep running, and resumes
here when the receipt is redeemed.
one thread 

there is exactly one thread running your code

while (true) {}          the whole tab stops. no clicks, no painting.

so nothing that takes time is allowed to block it
the network, timers, the disk — all hand back a promise
and let the thread get on with something else
Promise 

three states, and it settles exactly once

pending  →  fulfilled   with a value
pending  →  rejected    with a reason

const p = new Promise((resolve, reject) => {
  resolve('first');
  resolve('second');    ignored
  reject(new Error());   ignored too
});
await p                   → 'first'

you rarely write new Promise. fetch, timers and libraries
hand you one already made.
.then() 

the original form: hand over a function to run later
fetch(url)
  .then(res => res.json())
  .then(data => vis(data))
  .catch(err => visFeil(err))
  .finally(() => skjulSpinner());

each .then returns a new promise, which is what allows the chain
a value returned inside one becomes the input of the next
async await 

the same chain, written as if nothing took time
async function last() {
  const res = await fetch(url);
  const data = await res.json();
  vis(data);
}

async always returns a promise, whatever you write
async function en() { return 1; }
en()                       → Promise, not 1
await en()                 → 1

await works on things that were never promises
await 42                  → 42

and it only exists inside async (or at the top of a module)
function f() { await x; }   SyntaxError
try catch 

a throw inside async becomes a rejection
async function boom() { throw new Error('x'); }
boom()                     → a rejected Promise, not an exception

so ordinary try/catch works again
try {
  const res = await fetch(url);
  if (!res.ok) throw new Error(res.status);   lesson 6
} catch (err) {
  visFeil(err);
}

but a promise nobody watches is a silent failure
lagre();                   async, no await, no .catch → unhandled rejection
await lagre();             or lagre().catch(...)
Promise.all 

three independent calls, one after the other
for (const id of ids) await hent(id);     measured: 121 ms

the same three, started together
await Promise.all(ids.map(hent));       measured: 40 ms

all: one rejection rejects the whole thing
allSettled: never rejects; you get a status for each
race: the first to settle, good or bad
any: the first to succeed

const svar = await Promise.allSettled(kall);
svar.map(r => r.status)    → ['fulfilled', 'rejected']
microtask 

setTimeout(() => log('timeout 0'), 0);
Promise.resolve().then(() => log('promise'));
queueMicrotask(() => log('microtask'));
log('synchronous');

the order, every time
synchronous  →  promise  →  microtask  →  timeout 0

all synchronous code finishes first. then every waiting promise
runs, to the last one. only then does the next timer get a turn.

so setTimeout(fn, 0) does not mean "now" — it means
"after everything already queued, including promises"
