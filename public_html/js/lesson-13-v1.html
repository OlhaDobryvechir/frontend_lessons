encodeURIComponent 

encodeURIComponent('hei du')       hei%20du
encodeURIComponent('a&b=c')        a%26b%3Dc

it leaves only these alone:
A–Z  a–z  0–9  - _ . ! ~ * ' ( )

everything else becomes UTF-8 bytes, as %XX (lesson 6 of the HTML track)
'æ'      → %C3%A6      two bytes
'€'      → %E2%82%AC   three
'🙂'     → %F0%9F%99%82 four
encodeURI 

encodeURI('https://a.no/sok?q=hei du&x=1#topp')
   https://a.no/sok?q=hei%20du&x=1#topp   still a working address

encodeURIComponent('https://a.no/sok?q=hei du&x=1#topp')
   https%3A%2F%2Fa.no%2Fsok%3Fq%3Dhei%20du%26x%3D1%23topp
   no longer an address — now it is one value

the whole difference is these eleven characters:
   ; / ? : @ & = + $ , #
   encodeURI keeps them, because they hold the address together
   encodeURIComponent escapes them, because inside a value they are text

the one that bites: +
encodeURI('+')            +      and many servers read + as a space
encodeURIComponent('+')   %2B    a real plus
decode 

decodeURIComponent('hei%20du%20%26%20deg')   hei du & deg
decodeURIComponent('100%')                  URIError: URI malformed
decodeURIComponent('a+b')                   'a+b'   it does not know about +
new URLSearchParams('q=a+b').get('q')        'a b'   it does

encoding twice is the classic bug
encodeURIComponent(encodeURIComponent('hei du'))   hei%2520du
the % became %25, and the reader gets back 'hei%20du'

and the hash never leaves the machine
location.href = 'side.html?q=hei%20du#topp';
the server was asked for: /side.html?q=hei%20du
the page still sees: hash = #topp
