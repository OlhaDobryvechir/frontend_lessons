the same function, two ways — and four real differences

function doble(n) { return n * 2; }
const doble = (n) => n * 2;
function 

a declaration: hoisted whole, callable from above (lesson 3)
hilse();                      → works
function hilse() { ... }

an expression: just a value, assigned when the line runs
hilse();                      TypeError: hilse is not a function
const hilse = function() { ... };

a named expression — the name is visible only inside itself
const f = function ekte() { ... };
f.name                        → 'ekte'
ekte                          ReferenceError out here
=> 

(a, b) => { return a + b; }     full form
(a, b) => a + b               one expression: returned automatically
a => a * 2                    one parameter: parentheses optional
() => 42                      no parameters: parentheses required

the trap: braces mean a body, not an object
() => { navn: 'Ada' }         → undefined   (a label, then nothing returned)
() => ({ navn: 'Ada' })       → the object

they are anonymous, but the variable lends them a name
const doble = () => {};
doble.name                    → 'doble'
this 

a function gets its own this, decided by how it is called
an arrow has none, and uses the one from where it was written

const teller = {
  n: 7,
  medFunction() {
    return [1].map(function() { return this.n; })[0];   → undefined
  },
  medPil() {
    return [1].map(() => this.n)[0];                    → 7
  },
};

and an arrow cannot be talked out of it
pil.call({ n: 99 })            → still the outer this, not 99

what this actually refers to is the next lesson
arguments 

function klassisk() { return arguments.length; }
klassisk(1, 2, 3)                → 3

an arrow borrows the enclosing function's, which is rarely what you want
function ytre(a, b) {
  const indre = () => arguments.length;
  return indre(1, 2, 3);         → 2   it saw ytre's two, not its own three
}

with no function around it, there is nothing to borrow
const alene = () => arguments.length;   ReferenceError

the replacement works in both forms, and is clearer
const rest = (...a) => a.length;        → 3
new 

function Kunde() {}
const Pil = () => {};

typeof Kunde.prototype            → 'object'
typeof Pil.prototype              → 'undefined'

new Kunde()                       → an object
new Pil()                         TypeError: Pil is not a constructor
parameters 

these work the same in both forms
const f = (a, b = 10) => a + b;          a default
const g = (første, ...resten) => ...;     rest: gathers the remainder
const h = ({ navn, alder }) => ...;       unpacked from an object

a default only applies to undefined, not to every falsy value
f(1, undefined)                → 11   the default was used
f(1, null)                     → 1    null is a real value
f(1, 0)                        → 1

and length counts only the parameters before the first of those
((a, b) => {}).length          → 2
((a, b = 2) => {}).length      → 1
((a, ...r) => {}).length       → 1
choosing 

arrow      callbacks, short transforms, anything inside a method
           liste.map(v => v.navn)
           knapp.addEventListener('click', () => this.lagre())

function   methods on an object, and anything needing its own this
           { lagre() { ... } }

not an arrow   an object method that uses this
           { n: 1, les: () => this.n }     → undefined
