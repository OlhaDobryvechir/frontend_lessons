style — CSS written straight onto this one element
<p style="color: #58a6ff; font-weight: 700;">499 kr</p>

class — a name, and the CSS lives somewhere else
<p class="price">499 kr</p>

.price { color: #58a6ff; font-weight: 700; }
style 

a rule: selector, braces, declarations — in <style> or a .css file
p { color: #58a6ff; font-weight: 700; }

the attribute: declarations only, no selector, no braces
<p style="color: #58a6ff; font-weight: 700;">
declarations 

these have nowhere to live in a style attribute

:hover                          a state needs a selector
::before                        so does a generated box
@media (max-width: 600px)       and so does a condition
class 

one attribute, three names, separated by spaces
<p class="price price--campaign is-highlighted">499 kr</p>

.price             { font-weight: 700; }
.price--campaign   { color: #58a6ff; }
.is-highlighted    { background: rgba(88, 166, 255, 0.1); }
class vs id 

id      one name, one element, unique in the document   lesson 8
class   many names per element, many elements per name

both at once is perfectly normal
<h2 id="priser" class="section-title">Priser</h2>
     └ the jump target  └ the shared styling
