fetch() 

the shortest useful call
const res = await fetch('/api/kunder');
const data = await res.json();

two awaits, because two separate things take time:
first the headers arrive, then the body is read to the end

with everything spelled out
const res = await fetch('/api/kunder', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ navn: 'Ada' }),
});
response.ok 

a 404 is a perfectly successful fetch
const res = await fetch('/finnes-ikke');
res.ok        → false
res.status    → 404
no error was thrown. the server answered; you just did not like the answer.

fetch only fails when there was no answer at all
— no network, no DNS, blocked by CORS

so every call needs this
if (!res.ok) throw new Error('HTTP ' + res.status);
JSON 

JSON.stringify({ a: 1, b: undefined })     → '{"a":1}'      dropped
JSON.stringify([1, undefined])            → '[1,null]'     kept as null
JSON.stringify({ a: NaN })              → '{"a":null}'
JSON.stringify({ a: new Date(0) })       → an ISO string
JSON.stringify(new Map([['a', 1]]))     → '{}'           silently empty
JSON.stringify({ a: 1n })               TypeError
JSON.stringify(sirkulær)                TypeError

and nothing is restored on the way back
JSON.parse(JSON.stringify({ når: new Date() })).når   → a string

the format is stricter than Javascript
JSON.parse('{a: 1}')        SyntaxError — keys must be quoted
JSON.parse('{"a": 1,}')     SyntaxError — no trailing comma
methods 

GET      read something. no body. safe to repeat, safe to cache.
POST     create something, or anything that does not fit elsewhere.
PUT      replace the whole thing at this address.
PATCH    change part of it.
DELETE   remove it.
OPTIONS  ask what is allowed here. the browser sends these itself.

the distinction that matters in practice
repeating a PUT or a DELETE changes nothing more — idempotent
repeating a POST creates a second one — which is why double
clicks on a submit button are a real problem

await fetch(url, { method: 'GET', body: 'x' })   TypeError: GET cannot have a body
Content-Type 

what you are sending
Content-Type: application/json
Content-Type: application/x-www-form-urlencoded
Content-Type: multipart/form-data        file uploads

what you would like back
Accept: application/json

the classic bug: a JSON body without the header
fetch(url, { method: 'POST', body: JSON.stringify(data) })
→ the server reads it as text/plain and rejects it as malformed

and the opposite: with FormData, leave the header out
fetch(url, { method: 'POST', body: new FormData(skjema) })
→ the browser sets it, including the boundary marker you cannot know
CORS 

same origin = same scheme, host and port (HTML lesson 9)

for anything else, the browser asks permission first
OPTIONS /api/kunder
Origin: https://minside.no
Access-Control-Request-Method: PUT

and the server has to say yes
Access-Control-Allow-Origin: https://minside.no
Access-Control-Allow-Methods: GET, PUT, DELETE
Access-Control-Allow-Headers: Content-Type

what triggers that extra round trip
method is PUT, PATCH or DELETE
Content-Type: application/json           ← yes, this one too
any header you set yourself

with cookies, the wildcard is not allowed
fetch(url, { credentials: 'include' })
Access-Control-Allow-Origin: *           rejected
Access-Control-Allow-Origin: https://minside.no   accepted
