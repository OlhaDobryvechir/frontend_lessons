what does this refer to?             — decided how it is called

closure 

function lagTeller() {
  let n = 0;
  return () => ++n;          this function keeps n alive
}

const a = lagTeller();
a(); a(); a();                 → 1, 2, 3
const b = lagTeller();
b();                           → 1   its own n, not a's

it remembers the variable, not the value it had
let delt = 1;
const les = () => delt;
delt = 99;
les()                          → 99
this 

four ways to call, four answers

f()                  plain     → undefined in a module, globalThis in a script
obj.f()              method    → obj
new F()              new       → the fresh object
f.call(x)            explicit  → x

notice what decides it: the call, not the definition.
the same function gives four different answers.
losing this 

const teller = { navn: 'teller', les() { return this.navn; } };

teller.les()                   → 'teller'

const løs = teller.les;          the dot is gone
løs()                          TypeError in a module — this is undefined
                               in a classic script this is window instead,
                               so you read window.navn → undefined

and window already owns some of those names
{ name: 'Ada', les() { return this.name; } }
pulled off and called in a script → '' , because window.name exists

which is why this breaks
knapp.addEventListener('click', teller.les);       this is the button

and these do not
knapp.addEventListener('click', () => teller.les());
knapp.addEventListener('click', teller.les.bind(teller));
bind 

f.call(x, a, b)      call now, with this = x
f.apply(x, [a, b])   the same, arguments in an array
f.bind(x)            do not call — return a new function stuck to x

and a bound function cannot be bound again
const bundet = f.bind({ n: 'first' });
bundet.bind({ n: 'second' })()      → still 'first'

an arrow has nothing to bind (lesson 8)
pil.call({ n: 'x' })                 → the outer this, unchanged
module 

in a module, the top level is its own scope
const hemmelig = 1;
globalThis.hemmelig            → undefined

in a classic script, var and function do land on the global object
var gammel = 1;   window.gammel     → 1        (lesson 3)
const ny = 1;     window.ny         → undefined

modules are always strict, so a plain call gets undefined,
not the global object — which turns a whole class of quiet
bugs into an error you can see
